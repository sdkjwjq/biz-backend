**本次命令不恢复数据库，不覆盖业务数据，上传材料保持原样。不要添加 `--restore-backup`。** 包中保留的恢复能力仅供尚未执行此前已确认恢复操作的环境使用；显式增加该参数将使数据库回到 20260920backup.sql 时点，后续数据仅保留在更新前备份中。

本次步骤：文件校验 → 验证进程及空间 → 备份程序和前端 → 停止后端 → 完整备份当前数据库及 uploads → 补齐缺失结构 → 应用任务数据更新并校验 → 备份通知删除标记并清理失效提醒 → 启动后端并验证数据库连通 → 更新前端入口。

同一备份成功恢复后会记录标记，禁止重复恢复覆盖新数据。之后普通更新使用：

```bash
bash update.sh --update
```

普通更新补充结构并将失效的任务、绩效、成果待审核通知标记为删除，不导入旧备份，不修改任务、审核单、审核日志及其它业务记录。`bash update.sh --check` 只读检查，不清理通知。

清理范围：审核已完成、退回、撤回、业务删除，或已不再由消息接收人处理的待审核通知。保留当前仍需本人处理的待办、审核结果通知、督办及月度提醒。任务通知没有审核单编号，同一任务仍有待本人处理的审核时保留提醒。来源不明的通知不推测删除。

新后端会在审核状态变化时同步清理对应提醒，列表也会按当前状态过滤失效提醒。清理数量见更新输出及备份目录 `notice-cleanup.log`。独立恢复删除标记文件 `restore-notice-flags.sql` 仅含本次改动的通知 ID，不需要恢复整库；应用更新失败时脚本自动恢复这些标记。普通应用回滚保留通知清理结果。

## 本次功能

- 管理员新增"绩效关联任务编辑"：在绩效详情抽屉的"关联任务列表"旁点"编辑关联"，按抽屉当前年度勾选任务（可搜索、可全选、显示"已关联 / 待新增 / 待解除"），预览"新增 X 条、解除 Y 条"并填写原因后提交；只对 1.1.x / 1.2.x 这类由任务汇总的指标开放，手动填报指标不显示入口，专业群审核人与归口部门保持不变。
- 关联编辑整批校验、整批拒绝：任务必须是三级、未删除、数据类型不为 0、年度与指标年度一致，否则提示不会计入汇总或直接拒绝；该指标该年度存在审核中（10/20）单据时禁止编辑。提交后在同一个事务内重算绩效，完成值立即更新。
- 解除关联采用软删除留痕：`rel_task_performance` 增加 `is_delete` 列，关联行保留，重新挂回时复用原行，不会产生重复关联；绩效汇总与关联任务列表都只统计未解除的关联。
- 新增关联变更日志表 `biz_performance_relation_log`：记录指标、年度、动作（新增/解除）、任务、批次号、操作人与原因，管理员可在详情抽屉查看该指标本年度的变更记录。
- 绩效列表新增"关联任务数"列（仅管理员、仅自动任务指标显示）：显示当前年度已关联的任务数，便于发现没有挂任务的指标。
- 管理员新增"归属移交"：任务页与绩效页既可在详情抽屉单条移交，也可点工具栏"批量移交"；点击后表格才出现勾选列，勾选三级任务 / 绩效指标并点"确认移交（N）"进入填写弹窗，退出批量移交时勾选列随之隐藏，统一变更归口部门、责任人（负责人）与归口审核人三项，专业群审核人不参与移交。
- 移交采用"表单 → 变更预览 → 确认提交"两步式：预览显示"当前值 → 新值"、被移交条数与影响说明（部门完成率归属、可见范围、填报权限随之调整）；移交原因必填，长度 1–200 字，已完成任务与已归档绩效同样允许移交。
- 整批校验、整批拒绝：一次 1–200 条，目标部门、责任人与归口审核人必须是未删除的有效对象，且至少一项与当前值不同；存在未删除且处于审核中（10/20/30）单据的任务、存在审核中（10/20）单据的绩效会被阻断，提示中列出被阻断记录，不做部分成功。

- 新增归属变更日志表 `biz_ownership_change_log`：记录对象类型、对象 ID、对象编号与名称、批次号、操作人、原因、变更前后的归口部门 / 责任人 / 归口审核人。管理员可在详情抽屉查看该对象的归属变更记录，普通用户不可见，无记录时不显示该区块。

## 失败与回滚

失败时自动恢复旧程序和前端；如果已开始替换数据库，先恢复更新前数据库再启动旧程序。数据库自动恢复失败时保持后端停止并显示备份路径。

恢复过数据的更新需同时回滚数据库及应用：

```bash
bash update.sh --rollback-database /root/biz-backend/backups/release-实际日期时间-PID
```

回滚先停止写入并额外保存当前数据库到 `before-rollback-*.sql.gz`，再恢复更新前数据与应用。回滚后的在线数据回到更新前，更新后数据保留在额外备份中。不要把此命令当作重启。

普通增量更新可用 `--rollback 备份目录` 恢复应用；存在逻辑删除纪实时，禁止直接回滚到可能不识别删除标记的旧应用。任何回滚均不删除上传材料。
