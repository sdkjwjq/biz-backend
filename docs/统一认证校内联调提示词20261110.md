## 三、先做只读预检

1. 记录学校电脑时间、操作系统、Java、Node、MySQL 版本，以及当前项目 Git 头和未提交文件。只记录版本号，不记录环境变量的值。
2. 在学校内网浏览器确认可打开 `http://172.19.2.81/` 和学校认证主页；在 PowerShell 执行 `Test-NetConnection ca.xzcit.cn -Port 80`、`Test-NetConnection 172.19.2.81 -Port 80`。如学校提供 HTTPS 地址，再测试 443 并记录确切结果；不要自行改服务端地址。
3. 核对信息中心登记的接入地址、OAuth2 回调地址、业务系统退出地址。我们当前登记口径是接入／回调 `http://172.19.2.81/`，业务退出 `http://172.19.2.81/sso/logout`。请确认它们是否已登记、是否要求完全一致的尾部 `/`、是否允许增加**临时测试回调地址**。服务端 OAuth 地址基址是 `http://ca.xzcit.cn/cas`，授权入口是 `/oauth2.0/authorize`。不要把 app_key 或 app_secret 原文写入报告。
4. 只读请求 `http://172.19.2.81/api/system/sso/status`：记录状态码和 `enabled` 布尔值即可。若返回 404 或 `enabled=false`，说明线上尚未启用本次代码／配置，不要把它当成学校认证失败。
5. 若有权限查看**测试库**，确认我的学校认证工号在平台 `sys_user.user_id` 存在，账号 `status='1'` 且 `is_delete=0`。只报告工号后两位和是否匹配；不要输出密码或密码哈希。学校实际返回的标识若不是平台数字工号，记录字段名和脱敏样例，不按姓名猜测绑定。

## 四、选择可执行的联调路径

**优先使用独立测试回调。**如果信息中心允许临时登记如 `http://<学校电脑内网IP>:5175/` 的回调，在学校电脑上使用隔离数据库和当前前后端代码启动测试环境。后端只连接隔离库；`SSO_REDIRECT_URI` 必须与登记地址完全一致。前端可用 Vite 开发服务，`/api` 代理到本机后端。仅在本机私有会话中设置 `SSO_ENABLED=true`、`SSO_CLIENT_ID`、`SSO_CLIENT_SECRET`、`SSO_CAS_BASE_URL`、`SSO_REDIRECT_URI`，不打印值。确保端口可达后再用浏览器测试。

**若仅登记了 `http://172.19.2.81/`：**这表示真实授权码会回到线上服务器，学校电脑上的本地服务无法收到回调。此时只能完成只读预检；要做完整真实登录，必须先取得一个与登记回调一致的测试部署位置，或经我另行安排线上灰度部署。不要用手动复制授权码、改线上数据库或直接替换生产 JAR 来规避这个限制。给我一份明确的阻碍和可选方案。

## 五、具备测试回调后，用浏览器做真实流程

使用**我本人学校统一认证账号**，在 Edge 无痕窗口操作，记录每一步是否成功、时间和页面截图；截图遮盖姓名、工号中间位和地址栏中的 `code`、`state`。

1. 打开测试平台登录页，确认“学校统一身份认证登录”出现，同时原账号密码登录入口仍在。
2. 点击 SSO 按钮，确认跳到学校认证页。登录学校账号，确认浏览器回到**已登记测试回调地址**；平台自动处理授权码，地址栏中不再保留 `code`、`state`。不要把授权码原文放进报告。
3. 确认进入平台正常业务页；若该账号同时可信息填报和专家评审，先选择“信息填报”，再打开任务页。记录平台显示的身份和允许查看的菜单是否与账号原有权限一致。若页面提示未关联账号，只记录脱敏的学校返回标识和平台账号存在性。
4. 用同一个账号从业务页退出登录，确认平台本地会话失效，浏览器进入学校统一注销流程，再回到登录页。退出后直接打开业务 URL，确认不能继续访问。如果该账号有角色选择页，再登录一次，并在角色选择页点“返回登录”，也应走学校注销。
5. 再测试一次原平台账号密码登录（由我输入密码，Agent 不查看、不记录），确认原入口没有因 SSO 接入失效。若账号有强制改密标记，只观察与原规则一致，不重置真实用户密码。
6. 可用无害的错误回调测试 `state` 校验：直接打开测试回调的 `/?code=invalid&state=invalid`，应拒绝并提示重新登录，不建立平台会话；不要重放真实授权码。

每一步记录前端页面结果、相关平台接口的 HTTP 状态码和后端对应时间段的错误摘要。不要抓取、保存或发送请求头、Cookie、完整 URL 查询串及响应中的 Token。任何 400/403/500/502，先判断发生在平台、学校认证服务、账号映射还是网络层。
