# 管理员删除工作纪实

## 使用与接口

- 管理员在工作纪实列表点击“删除”，或打开已提交详情点击“删除纪实”。填写 1～300 字原因后确认。
- 仅数据库当前角色为管理员的账号可删除。指定查阅导出账号没有删除权限，他人草稿仍不可见。
- 采用逻辑删除，原文、填报条目、统计快照保留；记录删除人、时间、原因并递增版本。
- 删除后列表、填报人选项、详情及导出排除该记录；填报人可以重新创建该月份纪实，取得新 ID。
- `POST /work-records/{id}/delete`，请求 `{ "version": 1, "reason": "重复填报" }`。成功 200；参数错误 400、非管理员 403、已删除或不可见 404、版本冲突 409。
- 同一账号、年度、月份最多一份有效记录；多个已删除版本各自保留。事务内锁定并校验版本，旧请求不能删除新建记录。

## 验证

- 后端 26 项工作纪实隔离回归：包含原有 20 项及 6 项删除测试，覆盖当前角色鉴权、草稿隐私、正文和快照保留、失效链接与导出、原因和版本校验、并发删除、并发重新创建、多次删除、失败事务回滚。
- 迁移检查：旧记录正文不变、重复执行不重复加字段、无删除记录时可回滚、有删除记录时阻止回滚（重复尝试仍能正确阻止）。只操作随机隔离数据库。
- Playwright 7 项：普通填报人及指定查阅人无删除入口；原因必填和取消；模拟失败保留表单；390px 弹窗；真实删除及重复点击；同月重填和详情删除；11 条数据末页删除后修正分页。
- Playwright 的删除失败为模拟响应；成功删除、重填、权限、失效详情与导出、分页均调用真实接口。浏览器未捕获运行异常。
- 前端修改文件 ESLint、生产构建及后端打包。前端保留已有大文件体积提示。
- 脚本：`scripts/run-work-record-regression.py`、`scripts/ui-audit/work-record-delete.cjs`。截图及结果在 `target/ui-audit/evidence-work-record-delete/`。

## 部署

本次新增四个字段并调整月度唯一索引，**必须先迁移数据库，再更新后端，最后更新前端**。不要直接用新 JAR 连接未迁移的数据库。

1. 备份数据库、当前 JAR 和前端；停止后端写入。
2. 在已部署工作纪实基础表的库执行：

   ```bash
   mysql --default-character-set=utf8mb4 -uroot -p biz < 002_work_record_delete.sql
   ```

   SQL 位于 `scripts/work-records/002_work_record_delete.sql`，只增加字段及调整索引，不删除或覆盖已有业务记录；可重复执行。
3. 更新并启动后端，确认数据库连接正常；更新前端，使用管理员验证删除入口。

当前旧目录 `releases/shuanggao-update-20260920` 没有重新组装，**不包含本次删除功能和 002 迁移**。本次前端构建在 `biz/dist`，普通后端构建在 `biz-backend/target`；正式发布仍应沿用发布流程生成不内置本地数据库密码的 JAR，并使用服务器既有外部配置。不要把普通本地构建当作完整一键更新包上传。

## 回滚

- 尚未执行过删除：恢复旧应用版本后，可按需执行 `002_work_record_delete_rollback.sql`；先停止写入并备份。保留新增字段也不影响旧版本工作。
- **已经发生删除：不能直接恢复旧版本应用。** 旧版本不识别删除标志，会重新显示已删除记录，且不兼容同月份保留的多个版本。回滚 SQL 检测到已删除记录会主动停止，不丢弃存档。此时保留数据结构及删除过滤逻辑，使用修正版本；若确需恢复更早版本，须单独制定数据恢复方案。
- Git 回退使用对应提交的反向提交，不使用硬重置；保留原有未提交工作。
