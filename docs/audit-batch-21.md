## 21-1【中 / BUG】管理接口修改任务实际值后，自动绩效未同步

- 位置：`service/BizService.java:179`（`updateTask`）。
- 合成任务关联一条自动计算绩效，初始都为 0；管理员通过任务更新接口将实际值改为 7，接口成功，数据库任务为 7，绩效仍为 0；显式调用绩效刷新接口后才变为 7。
- 原因：管理更新只保存任务，没有调用任务提交、撤回等流程已有的绩效刷新逻辑。
- 影响：任务和自动绩效显示不同的实际完成情况，直到其他刷新操作触发。
- 建议：任务更新与受影响绩效刷新放入同一事务，复用既有汇总逻辑；如果修改年度或关联条件，应同时考虑旧关联与新关联。不在本项擅自限制管理员可修改字段。
- 本项使用管理接口，不声称当前页面已有对应编辑入口；证据中任务只有一个关联绩效，排除其他任务贡献。

## 21-2【中 / BUG】新增任务可保存倒置层级

- 位置：`service/BizService.java:147`（`addTask`）。
- 真实新增接口接受 `level=1`、`parentId=930001`，父节点实际为二级任务；保存后成为“二级下面的一级”。
- 原因：只检查父节点是二级、项目与部门符合要求，没有检查新任务自身必须是三级；第十六批的层级修复只在修改入口调用。
- 影响：新建记录违反已有层级约束，依赖任务层级组织树及统计的逻辑可能遗漏或错分。实测确认存储层级错误，未额外断言具体页面错分结果。
- 建议：新增时明确校验三级任务限制，并复用层级规则；非法层级拒绝写入，不静默强改为三级。

## 21-3【低 / BUG】允许同名账号，但按姓名预警因此失败

- 位置：`service/SysService.java:287`（`sendAlert` 查询接收人）、`mapper/SysMapper.java:99`。
- 新增一名合成老师，按昵称调用 `/system/alert` 成功；通过合法账号新增接口再创建一名同昵称、不同账号的老师后，相同预警请求返回 code=500、`MyBatisSystemException`，未新增通知。
- 原因：昵称不唯一，但 `getUserByNickName` 按单对象接收查询结果，多个同名结果无法映射。
- 影响：旧版按姓名预警接口无法服务同名人员。**当前 Report.vue 督办页面使用按 ID 的 `/system/notice`，不受本项影响。**
- 建议：优先按唯一用户 ID 寻址；兼容旧姓名参数时，同名应返回明确的需选人提示，不能任取一人或群发。
- 是否保留旧版姓名接口属于方案选择，修复前确认；不建议通过禁止人员同名绕开问题。
