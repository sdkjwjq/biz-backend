## 20-1【中 / BUG】一键完结可重复生成完整审批链

- 位置：`service/BizService.java:286`、`:310`、`:1610`。
- 合成任务真实提交后，同时调用管理员一键完结接口，两次均返回任务已完成；数据库新增两组 10→20→30→40 审批日志及两条“任务已完成”通知。
- 原因：独立的 `finishTask` 仍普通读取最新审核单，先检查后更新。上一批修复的普通审核入口未被本入口调用。
- 影响：相同任务被重复完结，审批轨迹和通知重复。本次实测最终任务完成，不声称最终数值错误。
- 建议：一键完结与普通审核、撤回共用审核单锁；获得锁后读取最新任务及审核单状态再执行，避免锁等待前的事务快照使后续读取仍过时。

## 20-2【中 / BUG】成果修改允许清空必填名称和级别

- 位置：`service/AchievementService.java:196`、`:224`。
- 创建合法且尚未归档的合成成果，再通过其创建账号把名称和级别改为空字符串，接口返回修改成功，数据库两字段长度均为 0，仍处于待审状态 10；同样参数调用新增接口则明确拒绝。
- 原因：修改接口未复用新增时的名称、级别必填校验。
- 影响：形成新增流程不允许的无名称、无级别成果，影响列表辨识及审批核对。
- 建议：新增、修改共用已有必填规则，失败时不写入；区分缺省字段与显式空值，保持现有完整更新接口契约。不涉及已忽略的已归档成果编辑权限。

## 20-3【中 / BUG】账号管理仍可写入空密码

- 位置：`service/SysService.java:323`、`:343`、`:393`；前端 `src/views/Login.vue:152`。
- 管理员新增账号时传空密码，接口成功，空密码调用登录 API 也成功；Playwright 使用该账号保留空密码登录，页面提示“请输入密码”，未发起登录请求。
- 另以六个空格更新另一合成账号密码，更新成功，旧密码失效，空格密码可通过 API 和页面登录。
- 原因：新增、修改用户经 `userDTO2User` 直接保存密码，未复用当前 `changePassword` 中已有的非空及空白校验。
- 影响：管理员可生成页面无法登录的空密码账号，也可绕过现有改密入口的空白密码限制。
- 建议：账号新增、修改与改密复用已经确认的密码规则；修改接口是否允许省略密码应保持既有契约，若要支持省略则明确按保留原密码处理，不直接清空。
- 边界：本次不新增复杂度、旧密码验证等业务规则，不改变账号状态或历史密码。空格密码在当前登录页能登录，不能把它描述为“页面无法登录”。第十五批修的是独立 `/system/password` 入口，本项为账号管理新增、修改入口。
