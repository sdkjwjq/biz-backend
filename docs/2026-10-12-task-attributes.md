# 第二批：任务类型与完成日期

## 操作路径

工作中心 → 任务 → 三级任务详情 → 基本信息 → 修改管理属性。

仅当前数据库中正常的管理员可修改；重点、困难可同时选择，未选为一般。计划完成日期独立于原起止时间及逾期规则。保存要求填写原因、预览变更并确认，旧版本保存返回409，失败保留表单。普通用户与领导只读查看。

任务筛选新增全部类型、一般、重点、困难、重点且困难；重点、困难分别包含同时命中的任务。列表、详情和 Excel 导出均显示新属性。筛选与现有年度、部门、责任人等条件取交集，并参与本次会话浏览记忆。

## 实际完成日期

只读，正常最终归档或管理员完结时，三级任务达到目标才记录首次时间；重复归档不覆盖，未达标归档不记录。沿用四级目标等权规则。

旧任务没有独立结束日期字段，页面三级任务原结束日期按所属年度年末展示，因此计划日期初始化为该年度12月31日。新建任务同样初始化，不改变原业务日期。

历史完成日期仅回填可证明的三级达标填报及最终归档日志。缺少日志、提交时间或达标值时留空；快照显示此前已完成但缺乏首次证据时保守留空。采用当前目标配置，不能还原没有版本记录的历史目标调整。

## 迁移与回滚

正向：`data/migrations/2026-10-12-task-attributes.sql`，幂等新增5个字段，不覆盖已调整的计划日期、既有标记和完成日期，不修改填报值与审批日志。

核对：`data/migrations/2026-10-12-task-attributes-check.sql`。

部署顺序为数据库备份 → 正向SQL → 核对SQL → 后端 → 前端。本批不制作更新包，也未修改用户本地业务数据库。

应用回滚使用对应提交的反向提交或上一版产物。字段回滚脚本为 `data/migrations/2026-10-12-task-attributes-rollback.sql`；存在管理变更、标记或实际完成日期时主动拒绝删字段，先备份并保留新增业务数据，避免丢失历史。

验证全部使用合成账号和随机隔离库，原有本地测试服务保留。前端静态检查与正式构建、后端打包均需完成。关键浏览器截图保存在同目录的 `audit-evidence/2026-10-12-task-attributes`。
