# 移交修复与操作逻辑巡检（2026-10-28）

## 本轮结论

任务移交的三类人员应分别配置：专业群负责人（填报人）`leaderId`、专业群审核人 `auditorId`、归口部门审核人 `principalId`；归口部门 `deptId` 是另一项组织配置。

此前界面、请求和更新SQL都没有专业群审核人字段，并明确保持旧值。本次补齐三类人员的预填、独立选择、变更预览、保存、接收人通知和归属变更记录。负责人和归口审核人同为一人并不证明数据被自动联动；本次没有依据姓名或部门批量重配既有任务，同人兼任会提示管理员核对。

## 保留的业务规则

- 任务仍执行“专业群审核→归口审核→双高办归档”；不新增或跳过环节。
- 绩效仍执行“专业群审核→双高办归档”。移交界面说明归口人员配置用于对应核心指标，避免误以为绩效新增审核环节。
- 同一人兼任只提示核对，没有凭空新增禁止兼任规则；三类人员不自动随另一个选择改变。
- 有在途任务/绩效审核单时普通归属移交仍整批拒绝；显式审核职责移交继续走原保护流程。
- 旧接口不传auditorId时保留原专业群审核人；批量记录审核人不一致且未指定统一值时分别保留。其他字段维持原有批量统一指定方式，不声称已全面重做批量移交。
- 不改写历史审核、填报和已提交纪实快照，不把专业群审核人与归口审核人批量设置成同一人。
