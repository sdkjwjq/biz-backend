# 专家评审与统一权限管理：开发记录

## 第一批：权限底座（2026-10-24）

已建立后端定义的功能目录、角色模板、个人允许／禁止覆盖及按模块的数据范围。未调整的账号采用 LEGACY 兼容模式，继续按数据库中的部门、领导配置、专用名单和业务责任关系取得权限；新专家使用 CUSTOM＋EXPERT，不继承普通账号或部门权限。数据库角色0的正常管理员始终具有全部权限。

任务范围支持全校、部门、一级／二级目录、固定三级任务及年度组合。目录、部门随当前任务配置动态变化，个人自定义范围替换该模块的角色范围。绩效、成果、核心指标、纪实和预算分别执行模块范围。消息只限本人，审核待办仍来自业务处理人关系，他人纪实草稿不因查阅授权而开放。

接入列表、直接详情、审核历史、材料下载和静态材料地址、关联任务、统计与导出。部分目录清除范围外的描述和人员，并按可见任务计算目录进度。权限或范围变化后，前端会清除旧浏览缓存。

权限配置、旧领导范围配置、账号与部门维护采用统一锁顺序；修改权限前后核对待办。新提交、审批流转及移交不能产生无权处理的新待办。角色或个人配置携带对象版本和全局权限版本，冲突返回409；密码、Token和业务文件正文不写入权限日志。

## 第二批：角色与个人权限管理

新增管理中心“角色与权限”，账号列表提供“配置权限”和“新增专家账号”。角色支持新增、复制、修改、停用及删除未使用的自定义角色。个人授权支持保留原业务资格或仅使用指定角色、功能继承／允许／禁止、年度及部门／目录／记录组合范围；有效权限显示来源和已有职责。

保存前展示新增、移除的功能、可见任务清单及受影响账号、待办。受阻待办禁止保存；冲突和请求失败保留输入。关闭未保存编辑会提醒，窄屏下弹窗内容可滚动。菜单、路由、业务按钮及审核中心分模块请求已接入有效权限，未授权模块不再导致整个审核列表加载失败。

外部专家可不绑定校内部门，资料更新仍保留专家权限配置。修复账号编辑提交不必要字段及未正确携带更新时间的问题。核心指标填报能力和纪实草稿的可编辑标记同步检查有效权限。

验证：账号5项＋概览9项＋权限25项，共39项真实接口联测通过；Playwright 8项通过（其中一项注入409验证失败保留输入，其余使用真实接口）；前端ESLint、正式构建通过。浏览器报告与截图位于 `target/ui-audit/permissions-management/`。专家评语模块继续在第三批完成。

## 第三批：专家评审与最终接入

专家评审已完成。一级任务支持总体评语，三级任务支持具体评语及原任务详情入口；每份最多2000字，按 Unicode 字符校验。专家默认进入专家评审页，可按年度、一级任务、部门、关键词和本人评审状态查询。任务详情中的专家评语区域仅显示本人意见，管理员进入正式意见查询。

同一专家、同一任务保留一个当前草稿，可保存、恢复、提交和修订。正式提交独立保存专家身份、任务编号名称、年度、真实操作者及实际获准任务范围。修订草稿不覆盖正式意见；不同年度编辑同一一级任务时，先提示当前草稿所属年度。一级任务只开放部分任务时明确标注部分范围，搜索和部门筛选不会暗中改变提交范围。

管理员仅查询、导出正式意见及修订历史；草稿仅本人可见。Excel 包含正式意见表和逐条范围表，范围较多时不会塞入单个单元格而截断。管理员代填必须显式开启管理员测试并选择专家，意见和导出均记录管理员实际身份。专家评语不写入任务审批日志，不修改完成值、状态或材料。

权限收紧、账号停用或任务删除后，专家不能继续访问对应任务或意见。一级任务仍可见但范围缩小时，包含已撤销任务的旧草稿、正式意见和状态也对专家隐藏；管理员仍能查询历史正式版本。

### 最终权限校验与待办移交

所有已部署权限结构的账号，包括未经个人配置的 LEGACY 账号，均执行统一功能和范围校验。LEGACY 表示资格由原角色、部门、专用名单和业务职责推导，不表示可以绕过权限。已知旧接口的权限拒绝改为明确的403；不可见的纪实对象沿用404。领导分管范围的看板统计仍不被其范围外的个人审核职责扩大。

补充四级目标责任人所属三级任务的查阅、手动绩效材料的年度范围检查，以及取消纪实填报资格后的本人既有记录查阅。个人禁止项仍优先于继承权限。历史全字段任务更新接口仅管理员使用，委派的移交操作使用专用接口，不能据此覆盖进度等无关字段。

权限变更预览发现受阻待办时，可点击“移交审核职责”。管理员先核对同一业务对象、同一阶段的待办及新处理人，再填写原因确认移交；系统同步实际审核配置、当前处理人和站内提醒，保留原提交人、填报、审批结论及日志。接收人必须具备有效权限和范围，归档接收人必须为正常管理员；配置或待办变化时409拒绝，失败整体回滚。

任务审核阶段移交调整相应的 `auditorId` 或 `principalId`；绩效归口职责对整项绩效生效。核心指标归口审核取自关联绩效 `principalId`，移交会同步该配置，已经提交的核心报告审核人快照保留；归档移交仅改变在途处理人。移交成功后保留原权限表单，要求重新预览再保存。

### 使用与手测路径

1. **新建专家：**管理员 → 管理中心 → 账号与组织 → 新增专家账号。填写未占用的数字编号和姓名，创建后进入权限配置。初始密码为账号编号，首次登录强制改密。
2. **限定评审任务：**管理中心 → 角色与权限 → 个人授权。外部专家采用“仅使用指定角色”并选择“专家”；在任务数据范围中指定年度、部门、一级／二级目录或固定三级任务。先填写原因、预览影响，再确认保存。
3. **角色模板：**角色与权限 → 角色模板。可复制模板后调整，多个角色的允许项合并；个人允许／禁止覆盖角色，个人范围替换该模块角色范围。管理员模板固定全权限。
4. **专家评语：**专家登录 → 专家评审。一级任务点击“总体评语”，三级任务点击“专家评语”或先查看任务详情。保存草稿后重开应恢复；提交后修改、保存草稿，旧正式意见仍保留；再次提交新增正式版本。
5. **部分范围：**仅授权一个一级任务下的部分三级任务，打开一级总评核对提示和范围清单。正式提交后撤销其中部分权限，专家不能继续看到涉及已撤销任务的旧内容，管理员仍可查阅正式历史。
6. **管理员查阅：**管理员 → 专家评审 → 正式意见查询，按专家、年度和任务查询；“意见及修订”查看历史，勾选正式意见可导出当前版本或包含修订历史。
7. **管理员代填：**专家评审 → 管理员测试，填写测试原因并启用；选择代填专家后填写。提交结果显示代填标识及实际管理员，退出测试后回到正式意见查询。
8. **收紧权限：**对有待办的审核人禁止审核，预览应阻止保存。使用“移交审核职责”完成处理配置移交后，重新预览再保存；原处理人旧 Token 立即失去相应操作权限。

菜单和按钮只是入口控制；授予功能不会自动将账号指定为任务填报人或审核人。实际职责应在业务配置／移交中维护，最终有效权限和职责可在个人授权页一并核对。
