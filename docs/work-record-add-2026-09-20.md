# 工作纪实逐项添加改革任务

按用户确认，仍从本人现有任务所属的一级改革任务中选择，不允许自由输入任务名称，不扩大统计范围。

第二部分采用单项选择和“添加任务”按钮。添加后生成独立文字区域并清空选择；已添加项目禁选，重复点击不重复添加。每项提供“移除任务”，已有文字时确认后才移除。兼容原有草稿、提交记录及 Word 导出。

验证：

- `scripts/ui-audit/work-records.cjs`：现有 14 项页面回归全部通过，包含保存恢复、字数、未保存提醒、重复提交、多窗口冲突、权限、旧响应和多屏宽。
- `scripts/ui-audit/work-record-add.cjs`：新增 3 组检查通过，包含已有草稿兼容、先选后加、重复添加防护、两项独立填写保存恢复、移除取消保留、390px 布局、提交只读及真实 Word 中两项内容和顺序。
- 新测试仅在随机隔离库增加合成任务；成功流程均走真实接口。浏览器运行异常为零。
- 修改文件 ESLint 和前端生产构建通过，仍有原有构建体积提示。
- 证据：`target/ui-audit/evidence-work-record-add/`，包含手机截图、结果和实际导出的 Word。

本次不修改后端业务接口或数据库结构。已有“管理员删除纪实”版本部署后，仅需更新前端。本地旧更新包未重新组装；若与管理员删除功能一起部署，仍须执行该功能的 002 迁移并同步后端。
