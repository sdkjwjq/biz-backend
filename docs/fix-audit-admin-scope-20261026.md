# 管理员审核中心计数与列表范围修复

## 问题及根因

20261026性能优化版中，侧栏和页头按真实管理员的全业务待办统计，但分页读取
`GET /list-filters/audits` 未进入 `AdminTestFilter` 的管理员上下文。
`AuditListPageService.todoCount` 又单独临时设置上下文，使同一响应的 `total` 和
`summary.todoCount` 使用不同范围。管理员没有本人分配待办时，可出现34待处理而列表0条。

修复仅增加审核分页、选项及定位等精确GET/HEAD读取入口的管理员上下文，继续通过数据库
当前角色、启停状态及Token校验；移除计数方法中的单独上下文模拟。未扩大普通账号权限。
业务审核、附件及归档操作仍使用原来的校验、事务和真实管理员操作记录。

## 范围

- 运行时代码仅修改 `AdminTestFilter.java` 与 `AuditListPageService.java`。
- 不修改数据库结构、业务值、审核状态或审核日志。
- 不修改前端；筛选继续只影响列表，待处理角标仍代表全部可处理待办。
- 从已发布20261026版本构建独立源码快照，排除暂停中的预算、成果及绩效历史等修改。

## 验证

`scripts/run-review-regression.py auditscope`：三个独立真实HTTP/MySQL用例，覆盖34条混合
业务分页、四类业务、条件清空、定位、实际审核、管理员留痕、普通账号、伪造请求头、
数据库降级及停用后旧Token失效。另运行原有 `admintest` 回归。

`scripts/ui-audit/audit-scope-consistency.cjs`：使用同一随机隔离库，对比线上同款旧JAR和
单项修复版本，前端均为已发布的生产构建。旧版34/0，修复版34/34；检查四页、条件查询及
重置、详情、刷新、窄屏、普通账号范围及直接链接，未出现浏览器运行错误。

证据保存在 `target/audit-scope-fix-20261026/`。测试只复制本地库结构并添加合成记录，
不写入用户调试库或线上数据库。源码及构建配置与基线逐项比较，仅允许上述两处运行时修改。

## 发布与回退

修复包 `shuanggao-update-20261026-r2` 沿用原有检查、完整备份、部署及回滚脚本。
前端、SQL、模板及更新脚本与20261026包逐文件保持一致。新JAR的数据库密码由服务器配置提供。
正常回退使用更新成功后输出的 `--rollback-database` 命令及对应备份路径。
本地制作修复包不代表已经部署到生产服务器。
