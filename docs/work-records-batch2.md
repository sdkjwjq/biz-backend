# 工作纪实第二批：列表、填报与提交

## 改动

- 新增独立「工作纪实」菜单和 `/home/work-records` 页面；菜单依据后端资格显示。原有特殊成果账号如确有纪实资格也能进入，原成果权限不变。
- 列表按年度、月份、填报人、草稿／已提交筛选，每页10条。新建只提供可填年度及非未来月份；同月已有记录直接打开。
- 详情包含五部分、统计截止及核实说明、滚动任务表和改革任务文字。统计范围不受勾选影响。
- 草稿允许空白保存；六种文本均按 Unicode 码点限制300字。提交至少一项改革任务有有效内容，后端复核改革任务归属和年度填报资格。
- 保存采用记录锁及版本条件更新；提交重新计算并冻结统计，正文、改革任务条目、状态和快照在同一事务中保存。并发旧版本返回409；已提交不能保存、刷新或再次提交。
- 移除已填写项目、返回列表、切换路由和关闭网页保护未保存内容。写请求期间禁用重复操作；读取请求取消并校验请求序号，旧响应不能覆盖新筛选或已离开的详情。
- 版本冲突和保存失败保留当前文字，提供明确的重新加载入口；重新加载也先确认丢弃未保存内容。刷新统计只更新统计及版本，不丢失未保存文字。
- 管理员、指定账号和其他填报人不能读取他人草稿。资格取消后本人草稿保留只读入口。

本批没有 Word 导出按钮，第三批审核后接入导出和最终打包。沿用第一批的三张表，本批不增加迁移。

## 接口增量

均位于 `/api/work-records`，使用平台现有登录保护和 ErrorVO：

| 接口 | 用途 |
| --- | --- |
| `GET /authors` | 仅返回本人草稿及有权查阅的已提交记录对应的填报人 |
| `POST /{id}/save` | 版本化保存草稿正文及改革任务条目 |
| `POST /{id}/submit` | 校验正文并重新计算统计，冻结提交 |

正文请求含 `version`、`entries`、`problems`、`nextFocus`、`otherMatters`。条目含 `reformTaskId`、`keyProgress`、`stageResults`、`typicalPractices`；名称及顺序由服务端生成，不信任客户端名称。文本允许空或null，拒绝非文本及超过300字。

详情增加 `entries`；权限增加 `canViewOwnRecords`，用于无当前资格但仍有本人记录的菜单入口。已有字段保留。
