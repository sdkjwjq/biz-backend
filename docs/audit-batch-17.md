基线：后端 6888e02，前端 a3dd058。本批仅审计，保留原有未提交改动。

## 17-1【中 / BUG】空部门负责人中断整批提醒

- 位置：`service/ScheduledTaskService.java:245`、`:55`、`:178`。
- review 隔离样本包含正常负责人 910002 和未配置负责人的部门 920002。分别调用月度、年度部门提醒接口，都返回空指针 ErrorVO；正常负责人新收到的提醒数为 0。
- 原因：获取全部负责人时保留 null，循环中按用户查部门后直接访问 deptId，未检查空值。
- 影响：一个尚未配置负责人的部门会影响其他已配置部门的正常提醒。
- 建议：过滤空/无效负责人并记录配置缺失，按有效部门继续处理；单个部门的缺配置不能中断其他部门。
- 此结论是同步手动入口实测。该入口调用与定时触发相同的提醒方法；未实际等待月初或年初调度时间。

## 17-2【中 / BUG】兼管部门的任务未计入提醒

- 位置：`service/ScheduledTaskService.java:55`、`:178`。
- 负责人 910002 账号所属部门为 A，另将 B 的 leader_id 配置为该用户。A 有 3 项任务，B 新建 2 项任务。
- 调用月度和年度提醒，各只生成一条通知，正文均为“本年度贵部门有 3 个双高建设任务”，B 的两项任务没有提醒。
- 原因：负责人去重后，使用账号自身 dept_id 查询部门，没有按 sys_dept.leader_id 找出其实际负责的部门集合。
- 影响：兼管部门的数据被遗漏；按负责人关系管理多个部门的现有权限模型与提醒查询不一致。
- 建议：以所负责部门为查询依据，按部门发送带部门名的提醒，或汇总后明确列出各部门。通知分条还是合并可在修复前选择。
- 这里保留原有“任务”统计层级口径，没有把统计一级/二级任务本身另列为 BUG。

## 17-3【中 / BUG】趋势记录失败仍返回成功

- 位置：`service/TrendDataService.java:102`、`:80`、`:145`。
- 将一个合成三级任务的 current_value 设为 null（表结构允许 null），调用真实 `/dashboard/trend/record` 返回“手动记录成功”，但趋势表仍为 0 条。
- 将同一个值改为 0，再次调用，返回同样提示，这次真实写入 1 条。对照说明先前并非“没有任务”或“今天已记录”的正常跳过。
- 原因：完成率计算直接对 current 调用 multiply；内部捕获异常仅打印日志，外层无法感知失败，仍固定返回成功。
- 影响：空值可导致整天趋势样本缺失，手动触发结果不能反映实际写入情况。
- 建议：按现有统计口径处理空实际值，同时明确区分写入成功、已记录跳过和失败；错误应向调用方传播，不能无条件提示成功。
- 未修改或重新提报已忽略的大屏无数据演示趋势问题。
