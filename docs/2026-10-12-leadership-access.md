# 第一批：校级领导查阅与只读管理概览

## 范围

本批只完成批准计划的第一批。任务标记与日期、独立核心指标、纪实资格调整及预算折线图留待后续批次审核后实施。没有制作服务器更新包，也没有修改本地业务库或服务器数据。

## 操作路径

管理员进入「管理中心 → 账号与组织 → 用户管理」，搜索账号，点击「查阅范围」。可设置全校、指定归口部门或取消配置；填写原因，核对变更前后内容后保存。

- 配置只增加读取能力，不修改账号原角色。
- 全校领导可读取全校任务、绩效；部门领导按三级任务／实际指标的归口部门读取。
- 本人已配置的责任人、专业群审核人及归口审核人职责继续有效；即使个别职责在分管范围之外，也可访问对应业务处理。该例外不扩大管理概览和大屏的分管统计范围。
- 目录保留用于树形浏览，任务目录进度按可见三级任务重新计算；绩效目录不暴露全校汇总值。
- 成果、预算和已提交纪实全校可读；其他人的草稿仍不可见。
- 管理概览保留全部卡片，任务、绩效及其异常明细按范围过滤；账号维护、异常处理等管理入口不向只读领导开放。
- 消息中心显示本人通知，可查看、标记已读，不显示「前往处理业务」。无明确审核职责的领导隐藏审核中心；原有明确审核／填报职责仍由原业务规则校验。
- 数据库当前角色和查阅配置在后续请求生效，不要求重新签发 Token。管理界面路由也读取当前权限。

## 初始化与数据安全

正向迁移：`data/migrations/2026-10-12-leadership-access.sql`。

新增两张查阅配置表与一张部门每日趋势快照表。根据提供的线上备份核实，仅初始化鲍桂楠 `110007` 和刘莹 `121552` 为全校查阅；同时核对账号姓名，避免错配。初始化使用 `INSERT IGNORE`，不会覆盖管理员后续取消或调整的配置，不按同名账号动态授权。不改账号角色、密码、任务值、绩效值或已有审批数据。

现有趋势表只有全校汇总，没有历史部门明细，因此无法可靠还原分管部门的旧趋势。部门趋势从部署后的每日采集开始保存；缺失历史留空。移除了大屏空数据时展示的示例趋势，避免将示例当成真实数据。

发布时先备份数据库，再应用迁移、执行核对脚本，最后更新后端及前端。核对脚本：`data/migrations/2026-10-12-leadership-access-check.sql`。本批不附更新包。

## 验证

测试均使用随机隔离库、合成账号与材料，不复制线上业务记录。

- 领导专项真实接口：全校与部门范围、目录汇总、详情／日志／附件越权、导出、即时变更、停用、旧管理员 Token、管理写操作拒绝。
- 真实并发修改：相同版本的两个请求只有一个成功，另一请求返回409；失败不增加成功日志。
- 权限取消：旧 Token 不能继续使用原领导详情链接；原有明确业务审核职责仍可操作。
- 纪实：领导可读取已提交冻结内容，无填报资格时不能新建；他人草稿不可读。
- 部门趋势：不返回全校历史记录，按部门计算，重复采集不重复生成每日快照。
- 迁移：两次执行不重复授权，同名其他账号不授权，后续取消不被重置；已有任务值不变。回滚脚本在已有配置时拒绝删表。
- Playwright：管理员配置、重复点击、领导只读概览与菜单、个人通知、部门范围、成果／预算页面访问、管理路由拒绝。

测试日志及截图在 `target/` 中；自动化入口为 `scripts/run-review-regression.py leadership` 和 `scripts/ui-audit/leadership-access.cjs`。完整业务回归入口为 `scripts/run-review-regression.py`，纪实回归为 `scripts/run-work-record-regression.py`。

本批执行结果：后端业务与领导专项合计73项通过，纪实回归27项通过，Playwright 9组检查通过且无页面运行异常，修改文件 ESLint 及前端正式构建通过。测试修复了一处真实并发旧快照读取问题：等待账号锁后，配置版本改为 `SELECT ... FOR UPDATE` 当前读，避免两个相同版本请求同时成功。

## 回滚

应用使用本批前后端提交的反向提交或上一版产物回滚，不执行硬重置。

数据库回滚脚本：`data/migrations/2026-10-12-leadership-access-rollback.sql`。先恢复应用版本；配置、管理日志和趋势快照先备份保留。只要配置或趋势表非空，脚本会主动停止，避免丢弃业务记录。无需修改原有任务、绩效、预算和纪实数据。
