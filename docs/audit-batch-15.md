## 15-1【高 / BUG】降权后旧凭证仍能删除账号

- 位置：`config/UserRoleInterceptor.java:29`、`config/JwtInterceptor.java:66`。
- 隔离实测：创建合成管理员 915001 并登录；原管理员通过更新接口将其角色改为普通用户 1。查询确认角色为 1，重新登录的凭证删除 915002 返回 403；降权前的旧凭证调用同一删除接口却成功，随后查询 915002 的 isDelete 为 1。
- 原因：鉴权仍取 JWT 内签发时的 role，虽然查询当前用户，却未采用数据库中的最新角色。
- 影响：撤销管理员权限不能阻止既有会话继续执行管理操作。
- 建议：统一按当前账号角色授权，或角色变更使既有凭证失效；同时检查其他业务中直接读取 JWT 角色的路径，避免仅修复一个入口。

## 15-2【中 / BUG，停用规则待确认】账号状态参数未保存

- 位置：`service/SysService.java:369`、`:380`。
- 隔离实测：新增 915003 请求 status=0，查询保存为 1；再以完整用户数据更新 status=0，接口提示成功，查询仍为 1。
- 原因：新增和修改共用 userDTO2User，内部固定 setStatus("1")，忽略请求字段。
- 影响：接口无法保存调用方指定的状态，更新成功提示与实际数据不一致。
- 建议：先确定状态码及历史数据含义，再校验并保存传入状态；未传字段沿用既有值或经确认的默认值。
- 边界：实体、DTO、前端 API 注释均标注 0 正常/1 停用，但现有转换及测试账号统一使用 1，登录和鉴权不检查该字段，实测 1 能登录。不能仅根据注释直接启用拦截或批量改历史值；停用业务语义及兼容方案须用户确认。确定的问题是传入状态被无条件覆盖，不将“停用登录”另拆为新 BUG。

## 15-3【中 / BUG】改密接口允许空密码，页面无法再登录

- 位置：`service/SysService.java:118`；`biz/src/views/Home.vue:449`、`Login.vue:112`。
- 隔离实测：915004 通过真实改密接口提交空字符串，接口成功；旧密码登录被拒绝，空密码直接调登录 API 能取得凭证。Playwright 在登录页填写该账号并保留空密码，点击登录提示“请输入密码”，没有发出登录请求。
- 影响：可将账号改成页面不接受的密码；仅前端存在非空/长度校验，接口不符合页面约束。
- 建议：后端拒绝空值、空白及不符合已确认长度要求的密码，返回明确错误并保证原密码不变；前后端保持同一规则。
- 边界：不在本项引入“必须输入旧密码”等未经确认的新业务规则。
