# 第二批后端修复记录

本批范围：跨年度绩效恢复、任务撤回边界和事务、绩效审核状态、年度任务启用。沿用现有接口和业务分层，每项验证通过后单独提交 Git。

## 1. 跨年度绩效恢复

- 改动：`PerformanceService.restorePerformanceSnapshot` 只恢复该年度实际值，再复用年度汇总方法更新总值；保留当前年度目标配置。
- 修复前复现：2026 年填 3、2027 年填 5，撤回 2026 年后总值错误变为 0。
- 验证通过：`performanceRollbackPreservesOtherYearsAndCurrentTargets`，覆盖撤回/退回 × 数值求和/百分比取最大值四种组合，另一年度、其审批单及当前目标均保留。

## 2. 任务撤回状态及事务

- 改动：`BizService.drawbackSubmit` 仅允许 10/20/30 待审阶段撤回，增加事务以覆盖审批单、日志、任务快照恢复和绩效刷新。
- 修复前复现：归档后仍可撤回；绩效写入失败时，之前的审批单和任务修改没有一起回滚。
- 验证通过：新增归档拒绝、三个待审阶段正常撤回/再次提交、数据库异常回滚三项 HTTP 测试；累计 11 项回归全部通过。异常由隔离库临时触发器注入，测试后移除。

## 3. 绩效审核状态边界

- 改动：`PerformanceService.auditPerformance` 在通过/退回分支之前统一校验，只允许 10/20 待审状态执行审核。
- 修复前复现：管理员再次退回已归档绩效，接口仍返回成功。
- 验证通过：归档、退回、撤回后的旧单不能再次改变数据；旧退回单不能覆盖新填报；正常两级审批、两个待审阶段的退回及权限校验保留。累计 13 项回归全部通过。

## 4. 年度任务启用

- 改动：新增 `BizMapper.startPendingTasksByPhase` 条件更新，仅将当年 `status=0` 且未删除的任务启用；历史空删除标记按未删除兼容。调度服务调用该方法，不再全字段逐行覆盖任务。
- 保留原定时和管理员手动触发入口；失败会返回错误，不再误报成功。
- 修复前复现：年度触发会修改非待启用任务，数据库异常也返回成功。
- 验证通过：当年未开始任务正常启用，进行中/审核中/已完成/已删除/其他年份/未知状态均保留；其他字段不变、重复触发不改数据，未授权调用被拒绝，数据库异常无部分更新。测试保留真实调度服务，只关闭测试进程的自动定时触发。

## 最终验证

- 本轮每项均先复现问题，再修复并回归；累计 **15 项 HTTP + MySQL 测试通过，0 失败、0 错误、0 跳过**，包含上一批 7 项回归。
- `mvn.cmd -B -DskipTests package` 构建通过，`git diff --check` 通过。
- 测试库和临时故障触发器已清理；未运行依赖业务库固定数据的旧测试类，未执行浏览器人工测试。

## 复测方式

在 `biz-backend` 目录设置进程环境变量 `SHUANGGAO_TEST_DB_PASSWORD` 后执行：

```powershell
python scripts/run-review-regression.py
mvn.cmd -B -DskipTests package
```

可追加单个测试方法名进行定向复测。脚本只读取本地 `biz` 表结构，在随机测试库内生成合成数据并启动随机端口 HTTP 服务，结束后自动删除测试库。测试源码和本文不记录本地数据库密码。

## 部署及回滚

本批无数据库结构变更或历史数据批量修改，无需迁移/回滚 SQL。部署沿用现有后端 JAR 和外置配置；回滚恢复原 JAR，代码可按独立提交逐项 revert。本次未部署或推送远端。
