第二十一批修复完成后继续审计，后端基线 `09a3abb`。本批仅审计，不修改业务代码，预算模块及已忽略事项不涉及。

## 22-1【中 / BUG】新增任务允许挂到已删除父节点

- 位置：`service/BizService.java:147`（`addTask`）。
- 将隔离库中的二级父任务标记删除，再通过管理员新增接口创建合法三级任务，返回成功；保存后子任务 is_delete=0，父任务 is_delete=1。
- 原因：新增只检查父任务存在、层级及部门，普通查询仍返回逻辑删除记录；修改入口已有已删除祖先校验。
- 影响：创建有效子任务却挂在无效父节点下，破坏有效任务树的引用关系。未声称实测了具体前端漏项表现。
- 建议：新增校验父任务及必要祖先未删除，复用既有层级校验；失败不写库。不同于上一批“子任务自身层级错误”，本例子任务三级合法。

## 22-2【中 / BUG】通知向已删除账号发送仍提示成功

- 位置：`service/SysService.java:236`（`sendNotice`）。
- 通过真实账号接口新增并删除合成账号 922201，再使用 `/system/notice` 发送通知，接口返回“发送成功”并保存收件人为 922201 的通知；该账号登录被拒绝。
- 原因：普通通知入口直接保存收件人 ID，没有校验逻辑删除状态。上一批修复的是独立 `/system/alert` 入口。
- 影响：发送者得到成功提示，但接收账号无法登录查看；仍持有旧账号选项的页面或调用方不能得知收件人已失效。
- 建议：发送前校验接收账号存在且未删除，失败给出明确提示；不新增未知的停用状态规则，不改变账号删除业务。
- 排除项：完全不存在的 ID 被现有数据库外键拒绝，并未写入，本次不报告“向不存在账号写入成功”。

## 22-3【中 / BUG】历史审核单缺少处理人会中断整批月度审核提醒

- 位置：`service/ScheduledTaskService.java:109`（`monthlyAuditorReminder`）。
- 正常待审单存在时，管理员触发月度审核提醒成功；再在隔离库加入一条 current_handler_id=NULL 的历史形态待审单，重试返回错误，本轮通知新增 0，正常审核人也未收到提醒。
- 原因：收集审核人时未过滤空值，随后直接对处理人调用 equals；缺失账号的情况也缺少防御，但本批只实测空处理人。
- 影响：一条异常历史记录阻断有效记录的提醒。
- 建议：跳过无有效处理人的异常记录并记录日志，正常审核人的计数及通知继续生成，返回实际发送与跳过数量。
- 边界：异常记录直接在随机测试库构造，表示历史脏数据容错，不声称修复后的提交接口仍能生成该记录。第十七批修复的是部门负责人提醒，本次为另一个审核人提醒入口。
